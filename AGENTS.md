# AGENTS.md

## Stack
- React 19 + Vite 8 + Tailwind CSS 4 (plain JSX, no TypeScript), `@tanstack/react-query`, `axios`, `react-router-dom@7`
- Tailwind v4 uses `@tailwindcss/vite` plugin — no `tailwind.config.js`/`postcss.config.js`; customization happens via `@theme` blocks in `src/index.css` (custom `animate-*` keyframes live there, incl. `prefers-reduced-motion` overrides)
- No test runner or typecheck configured. `eslint-plugin-react-hooks` v7 `flat.recommended` enforces **React Compiler rules at lint time** (immutability/purity) — see Gotchas.

## Commands
- `npm run dev` — Vite dev server
- `npm run build` — production build
- `npm run preview` — preview the production build
- `npm run lint` — ESLint (flat config, `eslint .`)
- Verification is `npm run lint` + `npm run build` (no tests). Build has a known >500 kB single-chunk warning — non-blocking. Lint currently fails with 3 pre-existing errors in committed code (unused var in `EquipmentPage.jsx`, setState-in-effect in `GoogleCallbackPage.jsx` + `GymProfilePage.jsx`) — don't attribute them to your changes.

## Architecture
- `STRUCTURE.md` documents the file tree with a one-phrase responsibility per file — consult it before adding/relocating files.
- `src/App.jsx` is a thin provider composition (`AuthProvider` > `BrowserRouter` > `PageTransitionProvider` > `AppRoutes`). The route table lives in `src/routes/AppRoutes.jsx`; route guards (`VerifiedRoute`, `GuestRoute`, `VerifyEmailRoute`) live in `src/routes/guards.jsx` and the post-verification redirect in `src/routes/EmailVerifiedHandler.jsx` — wrap new protected pages with `VerifiedRoute`.
- API layer is `src/lib/api.js` (axios): `baseURL` from `VITE_API_URL`, bearer token in `localStorage` key `auth_token`, 401 response interceptor clears the token and hard-redirects to `/login`. No Vite dev proxy — calls hit the backend origin directly.
- Backend is a Laravel API (sibling `backend/` folder, `http://localhost:8000` per `.env.development`). **All dashboard endpoints are implemented and wired** via `src/lib/dashboardApi.js` (`members`, `staff`, `equipment`, `checkins`, `gym`, `finances`, `user`); `unwrapList`/`unwrapOne` accept both bare arrays and Laravel `{ data: [...] }` resource shapes. Field errors arrive as `error.response.data.errors` keyed by field. Google sign-in/up is a full-page redirect to `${VITE_API_URL}/api/auth/google/redirect`; the callback route `/auth/google/callback` (`src/pages/GoogleCallbackPage.jsx`) stores the `?token=` query param and refreshes the user query.
- Auth state is TanStack Query: `AuthProvider` in `src/context/AuthContext.jsx` owns `useQuery({ queryKey: ['user'] })` and exposes `user`/`isLoading`/`isError`/`error`/`login`/`register`/`logout`/`refreshUser` via its value.
- Contexts follow an unusual split: the provider lives in `src/context/` (`AuthContext.jsx`, `BackgroundContext.jsx`, `DashboardNavContext.jsx`, `DataSourceContext.jsx`), while the `createContext` object + `useX` hook live in `src/hooks/` (`useAuth.js`, `useBackground.js`, `useDashboardNav.js`, `useDataSource.js`). Exception: `PageTransitionProvider` lives in `src/components/PageTransition.jsx` with its hook in `src/hooks/usePageTransition.js`. Keep new contexts on this pattern.
- **Dashboard data is live-first with a mock fallback.** Every module page delegates to `useSourceData({ queryKey, queryFn: dashboardApi.X.list, mockData, emptyValue, staleTime })` (`src/hooks/useSourceData.js`; `staleTime` defaults to 5 min so background-prefetched data stays fresh). The source comes from `DataSourceContext` (`src/context/DataSourceContext.jsx`, `localStorage['data_source']`): defaults to `'api'` when an `auth_token` exists, else `'mock'`; toggled in the DashboardLayout top bar. Live queries only run when a user is signed in (`enabled: isLive && !!user`). The hook returns `data, setData, isLive, refetch, isPending, isFetching, isError` (`isPending` is true only on the first live fetch with no data yet — it drives skeleton states). In mock mode `setData` mutates local state; in live mode mutations call `dashboardApi` then `refetch()`. Mock fixtures live in `src/lib/{members,staff,equipment,checkins,finances,gym}.js`; pure derivations in `src/lib/dashboardStats.js` (Dashboard) and `src/lib/financeMetrics.js` (Finances); shared presentation in `src/components/SectionHeader.jsx`, `src/components/dashboard/widgets.jsx`, `src/components/finances/`, and `formatMoneyCompact` (`src/lib/format.js`). `WIRING_PLAN.md` records the agreed scope + frontend↔backend field mappings (the wiring it specifies is now implemented; out-of-scope Settings features still show an "out of scope" toast).
- **Dashboard home is per-section.** `DashboardPage` runs one independent `useSourceData` query per section (`['dashboard-overview']`, `['dashboard-insights']`, `['dashboard-operations']`, `['dashboard-finances']`, `staleTime: 0`) against separate backend endpoints (`/api/dashboard/{overview,insights,operations,finances}` in `backend/app/Http/Controllers/Api/DashboardController.php`); presentational sections in `src/components/dashboard/sections/` render their own skeleton (`TileSkeleton`/`PanelSkeleton`) and retry banner. Module data (members/staff/equipment/checkins/finances) is **prefetched in the background** by `usePrefetchDashboardModules` (`src/hooks/usePrefetchDashboardModules.js`, mounted in `DashboardLayout`) once the current page's own queries have settled — it skips mock mode and only fills queries the current page doesn't already own.
- **Optimistic loading & error UX**: pages render their shell + a skeleton while requests run (`src/components/Skeletons.jsx`: `TableSkeleton`/`CardSkeleton`/`TileSkeleton`/`PageSkeleton`) and swap to `DataErrorState` (full-page Retry) or `DataErrorBanner` (compact Retry) on failure — no blank white screens. Route guards (`src/routes/guards.jsx`) render children while the `['user']` query is in flight and show `AuthErrorScreen` (Go back) when the auth request genuinely fails (any non-401 error); a 401 is treated as "not signed in" and redirects to `/login`. `html, body { background:#000 }` in `src/index.css` backs up the black theme.
- Page transitions: the global LEAN panel sweep (via `TransitionLink` for internal links and `usePageTransition().start(path)` for programmatic nav) applies to non-dashboard navigation. Intra-dashboard nav uses a **scroll transition** extracted into `useScrollTransition` (`src/components/dashboard/useScrollTransition.js`): it stacks the target page and animates `window.scrollTo`, down or up depending on sidebar order; exposed app-wide as `DashboardNavProvider`/`useDashboardNav().navigateTo` (used by `DashboardPage` quick-nav). Both short-circuit under `prefers-reduced-motion`. Dashboard pages/routes/order are defined once in `src/lib/dashboardPages.js` (used by both `AppRoutes` and the sidebar). `DashboardLayout` composes `Sidebar`/`MobileHeader` from `src/components/dashboard/`.
- Settings panels are presentational components in `src/components/settings/` (`AccountPanel`, `SubscriptionPanel`, `NotificationsPanel`, `SecurityPanel`, `PreferencesPanel`, `ThemePanel`, `DangerZonePanel`); `SettingsPage` owns all the UI state and passes it down (props down, events up). Shared form primitives/class strings live in `src/components/settings/form.jsx`, page constants in `src/components/settings/constants.js`.

## Conventions
- **When asked to point out which file is responsible for something**: consult `STRUCTURE.md` first to shortlist candidates, narrow the suspects using its one-phrase descriptions (and cross-refs in this file), then read the actual file(s) to confirm. Don't grep the whole codebase for something the doc already answers.
- All CSS via Tailwind utility classes; single entry `src/index.css`
- **Brand accent is lime** (`lime-400` fills, black text on lime, `text-white/90`+ on dark backgrounds) — use for CTAs/accents everywhere
- **Typography is Tailwind's default sans stack** — no web fonts; don't add external fonts unless asked (avoids font-swap layout shift)
- Assets are `.webp` in `src/assets/` (e.g. `landing-page-background.webp`, `login-side-picture.webp`, `signup-side-picture.webp`, `logo.svg`); original `.jpg`s are kept in `src/assets/original assets/` — prefer importing the webp
- Pages in `src/pages/`, components in `src/components/`
- Shared dashboard building blocks in `src/components/`: `PageHeader` (page title/actions), `Panel` (card), `SectionHeader` (section title/subtitle), `Pagination`, `src/components/dashboard/widgets.jsx` (`Tile` with `size="sm"|"md"`, `ShareList`, `Avatar`, `InsidePill`, `StatusDot`), and hand-rolled SVG charts in `charts/` (`DonutChart`, `BarChart`, `LineChart`, `Legend`) — **no chart library**. Chart dots use translucent `rgba(9,9,11,0.85)` fills because dashboard backgrounds are user-selectable, not a fixed dark color.

## Gotchas
- Hosted on Vercel: `vercel.json` rewrites all routes to `/index.html` — don't remove it or deep-link refreshes 404
- `.env.development` is the only env file; production builds must supply `VITE_API_URL` at build time. Env vars need the `VITE_` prefix to be exposed
- **React Compiler lint rules** (from `eslint-plugin-react-hooks` v7): no reassigning render-scope variables (`react-hooks/immutability` — build chart segment offsets with `reduce`, not `let offset = ...`), no `new Date()`/`Math.random()` in render (`react-hooks/purity`), no `setState` in effects (`react-hooks/set-state-in-effect` — split into keyed inner components instead). Violations fail `npm run lint`.
- **Scrollbar styling**: Chromium is styled via `::-webkit-scrollbar` pseudo-element rules in `src/index.css`; a global `scrollbar-width`/`scrollbar-color` on `*` overrides them in Chrome 121+, so the Firefox fallback is gated behind `@supports not selector(::-webkit-scrollbar)`. Don't "fix" the scrollbar with a global rule or Chromium shows a white track.
- `.opencode/skills/kmp-glassmorphism-ui/` targets Kotlin Multiplatform — ignore it in this React app (same for `.github/copilot/skills/`)
